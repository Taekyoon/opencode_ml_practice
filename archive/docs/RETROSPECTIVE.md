## 1. 시작하게 된 배경

**"타이타닉 생존 데이터 분류 모델"**이라는 대표적인 머신러닝 입문 문제에서 출발했다. 타이타닉 예제를 통해 이진 분류 파이프라인(데이터 전처리 → 모델 학습 → 평가)의 전체 흐름을 익힌 뒤, **반도체 실험실에서 생성되는 수치 데이터로 제품 failure 여부를 예측**하는 현실 문제로 확장할 수 있는지가 이번 작업의 핵심 질문이었다.

`askmeanything` 질문 방식을 통해 요구사항을 점진적으로 정리했다.

## 2. 요구사항 수집 과정

| 단계 | 결정 내용 | 근거 |
|------|-----------|------|
| 데이터 출처 | 가상 데이터로 시작 | 실제 데이터 공유 전 파이프라인 검증이 우선 |
| 문제 유형 | 이진 분류 (합격/불량) | 타이타닉 과 동일 구조 |
| 데이터 형태 | 수치형 (공정 + 측정 변수) | 온도·압력·두께·저항 등 실험 데이터 |
| 불량률 | 10% 이상 (균형에 가까움) | 표준 분류 모델 적용 가능 범위 |
| 처리 시점 | 배치 처리 (분 단위) | 실시간 저지연 불필요 |
| 알고리즘 | 로지스틱 회귀 | 해석 가능성 + 빠른 학습 + 소규모 데이터 적합 |
| 평가지표 | 정확도·정밀도·재현율·F1·AUC-ROC | 불량 탐지에 대한 다각적 검증 |

**핵심 결정**: 실제 데이터 없이도 전체 파이프라인을 재현 가능하도록 시드 고정 가상 데이터 생성 모듈을 먼저 만드는 것이었다.

## 4. 진행 과정에서 마주한 문제와 해결

### (1) 불량률 조정
- 초기 로짓 계수로 생성하니 불량률이 43% → 계수 조정으로 목표 10~16%에 근접 → 최종 16.7%.
- **교훈**: 합성 데이터는 라벨 비율도 재현 가능해야 하며, 비즈니스 요구 정도의 편차가 크면 성능 지표가 의미를 잃는다.

### (2) 재현성 검증
- 시드 고정(`random_state=42`, `default_rng(42)`)으로 캠퍼스 재실행 시 MD5 해시가 정확히 일치.
- 파이프라인 두 번 실행 시 평가 지표 소수점 이하 수준까지 동일함을 검증.

### (3) matplot 한글 깨짐
- 기본 `DejaVu` 폰트에 한글 글리프가 없어 `Apple SD Gothic Neo`를 지정해 해결.

### (4) 노트북 실행 시 plot 경로 문제
- `evaluate()`의 상대경로(`plots/`)가 노트북 실행 디렉터리에 따라 `notebooks/plots/`를 만들던 문제를 발견 → `os.path.abspath("../plots")`로 루트 통일.
- 노트북 실행 회귀 후 교차 검증 셀의 import 누락(`cross_val_score`)을 찾아 수정.

### (5) 검증 방법
- 단순 실행뿐 아니라 **재현성·stratify 균형·표준화 수학 검증·결측 처리수 검증·노트북 전체 실행**까지 자동 검증 스크립트로 확인했다.

## 5. 도달 한 성능

| 지표 | 테스트셋 | 비고 |
|------|----------|------|
| Accuracy | 95.1% | 균형/가상 데이터라서 높음 |
| Precision | 89.9% | 불량 예측의 정확도 |
| Recall | 79.6% | 불량 탐지율 (상대적으로 낮음) |
| F1-score | 84.4% | 정밀-재현 조정 |
| AUC-ROC | 0.986 | 분류 능력 우수 |
| 5-Fold CV Accuracy | 0.946 ± 0.006 | 과대적 없이 안정 |

**해석**: 불균형(거의 6:1) 때문에 정밀도보다 재현율이 낮다. 실제 불량 1건처리에 대한 비용을 잘 계수해야 한다.

## 6. 이번 작업을 통해 얻은 것들

1. **이진 분류 파이프라인 템플릿 확보** - 타이타닉에서 시작한 구조가 반도체 실험 데이터에 그대로 확장됨을 증명.
2. **도메인과 관계없는 공통 루트**: 결측 처리, 표준화, 계층/stratify, 교차 검증, 불균형 지표 해석은 도메인이 바뀌어도 재사용 가능.
3. **검증 습관의 가치**: "데이터 → 모델 → 평가"만이 아니라 "재현성 검증 → 노트북 실행"까지 확인하니 신뢰도가 크게 올라갔다.
4. **모델 선택의 근거 강화**: 로지스틱 회귀는 해상성·속도·해석 관점에서 실험실 규모에 적절하다는 결론.

## 7. 아쉬웠던 점 / 한계

- **가상 데이터이다**: 장비/측정 노이즈와 공정 곡선이 단순 선형 결합일 뿐. 실제 실험실 열가/플라즈마·도달 공정은 비선형·다중 상호작용이라 성능이 낮아질 수 있다.
- **특성 공학 부재**: 시간 시퀀스, 공정 단계 이력, 센서 상관 관계같은 도메인 특화 특성 없이 기존 7개만 사용.
- **불량률 수준 검증 부족**: 도메인에서 흔한 0.5% 같은 초저불량률 케이스는 이 당시 다루지 않았다 (가상에서는 16.7%).
- **모델 1개만**: 랜덤 포레스트·XGBoost와의 성능 비교 없음.

## 8. 앞으로 확장할 것

1. **실제 반도체 실험 데이터 적용** - `data/synthetic_data.csv`를 실측 CSV로 교체하고 열 이름만 맞추면 동일 파이프 라인 재사용 가능.
2. **특성 공학 확장**: 공정 단계 순서, 시간 시퀀스(TS), 장비 ID 직중 호, 물리 지식 기반 파생.
3. **초불 균형 대응**: `class_weight='balanced'`, SMOTE, 임계값 최적화, PR-AUC 중심 평가.
4. **모델 비교**: 로지스틱 회귀 vs 랜덤 포레스트 vs XGBoost(Optuna 하이퍼파라미터 튜닝).
5. **해셜 가능 및 배치화**: `joblib` 모델 저장, 새 롯 단위 캐싱 추론 스크립트.
