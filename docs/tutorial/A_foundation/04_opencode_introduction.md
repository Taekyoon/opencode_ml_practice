# A4. opencode 시작하기 — AI 코딩 도구와 프로젝트의 관계

## 학습 목표
- opencode가 이 프로젝트에서 하는 역할을 이해한다
- `AGENTS.md`가 왜 중요한지 안다
- opencode와 대화하며 파일을 읽고 실행하는 법을 익힌다

## 배경 지식

### opencode는 무엇인가?
opencode는 터미널에서 대화로 코딩 작업을 하는 **AI 코딩 에이전트**다.
"파일을 만들어 줘", "이 코드를 설명해 줘", "이 실험을 실행해 줘" 같은 지시를
말로 하면 파일을 읽고, 수정하고, 명령을 실행한다.

### AGENTS.md: 성공 열쇠
이 프로젝트의 루트에 `AGENTS.md`라는 파일이 있다.

```markdown
# AGENTS.md — 반도체 Failure 예측 프로젝트 작업 가이드
> 이 문서는 opencode가 이 프로젝트에서 작업할 때 반드시 먼저 읽고 따라야 할 ...
```

AGENTS.md는 opencode에게 **"이 프로젝트의 규칙"**을 알려주는 문서다.
- 어디에 무엇이 있는지 (디렉터리 구조)
- 새 태스크를 어떻게 만드는지 (스캐폴드 사용)
- 코드 수정 규칙 (src/는 신중히, research/는 자유)
- 실험 기록 규칙 (위키)

> **핵심**: opencode는 AGENTS.md를 읽으면
> "이 프로젝트의 전문 연구원"처럼 행동할 수 있다.
> AGENTS.md가 없는 채로는 매번 설명해야 하므로 비효율적이다.

## 따라하기

### 1단계: opencode 실행
```bash
cd ~/opencode_ml_practice
opencode
```
대화가 시작된다. (종료는 `/exit`)

### 2단계: AGENTS.md 읽었는지 확인
opencode에 물어본다:
```
AGENTS.md를 읽었어? 이 프로젝트의 가장 중요한 규칙 세 가지를 알려줘.
```
잘 대답하면 이 프로젝트 규칙을 이해한 것이다.

### 3단계: 질문해보기
```
이 프로젝트에서 새 연구 태스크를 추가하는 방법을 정리해줘.
```
`scripts/new_task.py` 사용법이 설명되는지 확인한다.

### 4단계: 실행을 부탁해보기 (안전한 것)
```
src/data_generation.py를 실행해서 데이터를 다시 만들어줘.
```
명령이 실행되고 `data/synthetic_data.csv`가 갱신된다.

### 5단계: 수정을 부탁해보기 (꼭 필요한 경우만)
수정을 요청할 때는 **목적을 명확히** 말한다. 예:
```
experiment_runner.py의 get_config()에서 모델을 random_forest로 바꿔줘.
```
에이전트가 파일을 수정한다. `git diff`로 변경 내용을 확인해보자.

## 주의사항 (opencode 사용 팁)

- **변경 전에는 무슨 일이 생기는지 예상한다** — 맹목적으로 승낙하지 않는다
- **작은 변경을 요청하고 결과를 확인한다** — 한 번에 너무 많은 요구를 하면 차이 트래킹이 어렵다
- **실험 코드는 research/에, 코어는 src/에** — AGENTS.md가 정한 경계를 유지한다
- opencode가 "이건 수정하면 안 돼요"라고 하면 (예: src/ 코어 무단 수정) 그 이유를 물어본다

## 이해 확인

1. AGENTS.md가 opencode에 반드시 필요한데, 없는 프로젝트라면? (초안을 만들 수 있다)
2. opencode에게 수정을 요청할 때 어떤 정보를 주는게 좋은가?
3. `src/`를 자주 수정하면 왜 위험한가?

어떤 것이 자동화에 적합한지 판단해줘.
