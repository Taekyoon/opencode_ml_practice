# G4. 나만의 가드레일 — 배운 것을 종합하는 자유 실습

## 학습 목표
- 프롬프트 가드레일의 "데이터 → 학습 → 서빙" 전체 사이클을 자유롭게 확장한다
- 새 공격 유형·새 기준을 스스로 설계해보고, 한계를 기록한다
- 튜토리얼 수료를 마무리한다

## 배경 지식

G1~G3은 가이드에 따라 만들어 간 과정이었다. 이제 나만의 과제로 확장해보는 시간이다.
이 지점은 모듈 F의 F-1 "나만의 태스크"와 같은 패턴이다. 정답 하나가 있는 것이 아니라,
가면 갈수록 다양한 시도를 할 수 있는 자유 영역이다.

가드레일을 개선할 수 있는 자유 실습 아이디어:
1. **새 공격 유형 추가** — "재정 조작", "다국어 공격", "프롬프트 유출 방지 등
2. **임계값 전략 설계** — 서비스 타입(공개 채팅 서비스 vs 사내 도구)에 따라 원하는
   오탐/오탐 기준을 정하고, threshold를 튜닝한다
3. **규칙 기반 보완** — 키워드 필터 + 분류 모델을 이중으로(키워드에 걸리면 우선 정지)
4. **더 좋은 모델 도전** — TF-IDF 대신 문맥 표현 모델을 쓰면 하드 케이스가 얼마나
   개선되는지 (실제 도입은 비용 평가가 필요)

## 따라해보기 (자유 실습)

### 1단계: 플랜 (하려는 확장을 한 문장으로)
예: "새 공격 유형 'role_play'를 추가하고, 하드 케이스에서 통과하기 어렵게 한다"

### 2단계: 내 아이디어를 데이터/코드로
- 새 라벨을 만들면: `src/generate_prompt_data.py`에 템플릿 추가
- 임계값 전략만 바꾸면: `research/prompt_guard/predict.py`의 `is_unsafe`
- 모델 바꾸면: `research/prompt_guard/experiment_runner.py`의 `get_config()`

### 3단계: 검증 (A/B — 비교하고 되돌리기)
한 번에 한 변수만 바꾸고 결과를 `results/`에서 비교한다.
개선되지 않으면 되돌리고 다음 시도를 기록한다.

## 이해 확인
1. "hard_eval 정확도"와 "합성 데이터 정확도" 중 무엇을 기준으로 개선을 판단해야 실용적인가?
2. 새 공격 유형을 추가했을 때 반드시 함께 갱신해야 하는 파일은? (스크립트/러너/predict)
3. G1~G3에서 배운 것 중 이 실습에 가장 도움이 된 것은 무엇이었나?

## opencode에게 물어보세요

```
src/generate_prompt_data.py에 새 공격 유형 하나를 추가해보고, 데이터를 다시 만들어서
실행해줘. 리그레이션(오탐 증가)이 생기면 원인을 설명해줘.
```

## 수료 안내

모듈 G까지 봤다면:
- 텍스트 데이터를 다루는 법 (B5·B6)
- 가드레일 모델을 만들고 임계값으로 튜닝하는 법 (G1·G2)
- 학습 모델을 서비스 흐름에 얹는 법 (G3)
- 스스로 확장하는 법 (G4)

이제 이 프로젝트는 여러분의 것이다. 질문이 있으면 언제든 튜브랄로 돌아올 수 있고,
원하지 않으면 여기서 개인 실습을 이어가면 된다.
모든 모듈을 완주한 것을 축하합니다.
